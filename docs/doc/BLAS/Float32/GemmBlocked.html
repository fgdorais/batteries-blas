    Blocked gemm #

    PMat.gemmBlocked computes gemm by blocked loops, about twice as fast, with the same result: each element of C gets the same terms in the same order.

    The work is split into small functions: plain recursive loops over the blocks, the columns and the terms, which call in-place sweeps over the rows. A single in-place program with all the loops nested would pass every variable of the outer loops through the inner ones, which spills them in the innermost loop and, past a few levels, keeps the C compiler from turning the calls between the loops into jumps.

                      def BLAS.Float32.PMat.gemmBlocked {m n k : Nat} (α : Float32) (A : PMat m k) (B : PMat k n) (β : Float32) (C : PMat m n) :
                      PMat m n

                      gemmBlocked α A B β C is gemm α A B β C, by blocked loops that are about twice as fast. It scales C by β, then, for each block of 128 terms l and each block of 256 rows of C, it sweeps the rows of the block for two columns of C and four terms at a time: each sweep reads four columns of A and updates two columns of C, and the C compiler vectorizes it. The last column, when n is odd, and the terms that don't make a group of four go one at a time. Each element of C gets the same terms in the same order as in gemm, so the result is the same, which gemmBlocked_eq proves.
