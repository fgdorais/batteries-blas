    Specifications of loops #

    What the kernels need beyond scalar-arrays' models of loops: foldUpTo, a reduction over USize indices, a few element lemmas, the elements of iterRange loops over contiguous windows, which the gemm kernels use, and the algebra of modifyAt at the indices of a stride.

    scalar-arrays gives the models of loops, iterRange and Float64Array.modifyAt, the InPlace.Tail lemmas that run a loop to them, and Stride, with Stride.Fits for a stride whose indices are distinct and in bounds.

    Scaling by β #

    source
    @[inline]
    def BLAS.Float64.betaMul (β v : Float) :
    Float

    β * v, or 0 when β = 0, without reading v: the reference BLAS scales y or C by β this way in gemv and gemm, so that a NaN or an infinity in them doesn't survive β = 0.

    • BLAS.Float64.betaMul β v = if (β == 0) = true then 0 else β * v

      @[specialize #[]]
      def BLAS.Float64.foldUpTo {β : Type u} (n : Nat) (f : (i : Nat) → i < n → β → β) (fu : (i : USize) → i.toNat < n → β → β) (init : β) :
      β

      Nat.fold n f init, as a loop over USize indices when n < USize.size, which holds for the size of every array in memory, and as Nat.fold otherwise. It keeps a scalar β unboxed.

      The loop runs fu, a version of f that takes the index as a USize, so that it can read arrays with uget. A step that took a Nat index would convert it from USize and back at every element, which costs about a third of a reduction's time. foldUpTo_eq needs fu to agree with f.
